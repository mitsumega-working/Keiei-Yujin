# 形影遊刃 開発計画

設計は `design.md`。ここはフェーズと成果物だけ。

## Phase 1 — コア（Python パッケージ）＋ CLI
- [x] STEP 読み込みとハッシュ固定、TopExp 順のID付け
- [x] 平面分割、円筒分割、任意道具での分割（`partition_with`）
- [x] 系譜ID（Modified / IsDeleted から付与、兄弟順序規則、`created_by`）
- [x] 再生の決定性テスト（別プロセスで一致）
- [ ] 生成操作: 文字スケッチ（線・円弧・スプライン・オフセット、ID参照で座標指定）、押し出し、スイープ（build123d）
- [ ] 依存解決: 操作削除時に ID 参照から影響範囲を列挙（参照切れの診断は `mesh.check_references` に最小実装あり）
- [ ] 形状検査: BRepCheck_Analyzer、自由辺・微小辺の列挙（読み込み直後と各操作後）
- [ ] テッセレーション出力（面IDつき三角形、拡張向け JSON）
- [x] CLI `keiei-yujin replay` / `keiei-yujin mesh`

## Phase 2 — メッシュ層
- [x] 系譜ID → Gmsh タグ（TopExp順＝Gmsh順の検算付き）
- [x] メッシュ設定: サイズ、3Dアルゴリズム、transfinite 自動、稜線シード
- [ ] ソリッドごとの切り方（テトラ／構造／スイープ）の指定と判定プローブ（6面体か、スイープ可能か）
- [ ] 分割数の整合チェック（まずは Gmsh transfinite に委ね、矛盾は検出だけ）
- [x] テトラ: Delaunay ＋ OptimizeNetgen、品質報告（gamma / minSJ）
- [ ] 2次要素（中間節点順序を FrontISTR 342/362/352 と照合してから）
- [x] FrontISTR writer: 341/361/351、面番号表、内部面 SGROUP の `side`、NGROUP/EGROUP
- [ ] 反転要素の検出を writer の前に
- [ ] 形影転写で開いて名前と面が一致することの確認

## Phase 3 — ファイル形式
- [ ] 文法の確定（現状は JSON の仮形式 `examples/ogrid_hex.json`）
- [ ] パーサ／シリアライザ、往復で等価
- [ ] 診断（行番号付き）: 参照切れ、未割当領域、6面体でない領域に構造指定、形状検査

## Phase 4 — VS Code 拡張（MVP）
- [ ] CLI を呼んで JSON を受け取り表示（コアのロジックは持たない）
- [ ] 操作ツリー／名前リストのビュー、クリックで 3D ハイライト（生成物は強く、割られた側は弱く）
- [ ] テキスト ⇄ 3D の転写
- [ ] B-rep 表示と和柄塗り分け（画面固定、組子風ウッドカラー）
- [ ] メッシュ実行と結果表示、診断表示、パートの色分け
- [ ] 応答が遅ければ `serve` モード（契約は変えない）

## Phase 5 — 実戦検証
- [ ] 実案件に近い STEP（アセンブリ、隙間あり、フィレット付き）で分割→ヘキサ／テトラ→FrontISTR 実行まで
- [ ] 接触界面の扱い（融合しない組み合わせ）と SGROUP `side` の検証
- [ ] スイープ方向の連鎖と分割数整合（必要ならインターバル割り当てを自前実装）

## TO-BE
- DXF スケッチ読み込み（ezdxf）、曲面への投影分割
- FrontISTR へのピラミッド要素実装（ソルバ側）
- SMESH エンジン（ソリッドごとの別アルゴリズム）
- 稜線だけの埋め込みの確認

## マイルストーン
- M1: STEP＋操作ログ → テトラの FrontISTR msh（CLI のみ）— 最小縦断は済み。残りは生成操作と形状検査
- M2: 分割＋シードで全ヘキサ（済み: `examples/ogrid_hex.json`）、ヘキサ＋テトラ混在（ピラミッドは TO-BE）
- M3: 拡張 MVP
- M4: 実案件で一周して公開
